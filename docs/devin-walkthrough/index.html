01 — Introduction

Meet Devin, the AI
Software Engineer

Built by Cognition AI, Devin is an autonomous AI software engineer that can write, run, and test code end-to-end. If you can do it in three hours, Devin can most likely do it.

⚙

Autonomous Engineering

Devin operates with its own shell, IDE, and browser. It reads codebases, plans implementations, writes code, runs tests, and opens PRs — all without constant guidance.

⚡

Parallel Task Execution

Tackle many tasks simultaneously. Devin can run multiple sessions in parallel — delegating sub-tasks to child sessions for maximum throughput.

🛠

Full Dev Environment

Each session has a full Linux VM with shell, browser, and IDE. Devin installs dependencies, builds projects, and tests applications end-to-end inside its environment.

📚

Knowledge & Playbooks

Devin learns from your codebase via Knowledge notes and follows reusable Playbooks — shareable prompt templates that standardize complex workflows across your team.

Key strengths: Jira/Linear tickets, code migrations & refactors, bug reproduction & fixes, writing tests, PR reviews, building integrations, maintaining documentation, and security auditing.

03 — Event-Driven Automation

Automated Security Review
Pipeline

An end-to-end event-driven workflow where GitHub Issues automatically trigger Devin security reviews via the API, and results are reported to a live dashboard.

Devin API: v1 vs v3

Why v1?

The security workflow uses the Devin API v1 endpoint (POST /v1/sessions) because it is compatible with Pro accounts. The v3 API requires ACU quota allocation only available on Enterprise/Teams plans.

Featurev1v3
Endpoint/v1/sessions/v3/organizations/{org}/sessions
AuthPersonal/Service API keyOrg-scoped API key + Org ID
Pro PlanSupportedNot supported
ACU QuotaNot requiredRequired

How the Automation Works

When a security vulnerability is reported via GitHub Issues, the entire review lifecycle is automated end-to-end:

Step 1
Issue Created
Issue opened with "security" in title or labeled security-vulnerability
Step 2
GitHub Actions
Workflow validates issue, checks for duplicates, extracts context
Step 3
Devin API Call
POST /v1/sessions with issue context & security prompt
Step 4
Devin Reviews
Classifies vuln, traces code, assesses severity, implements fix
Step 5
PR & Report
Opens PR with fix + tests, comments findings on the issue

Example: Issue #7 — XSS in SQL Lab

The Vulnerability

XSS OWASP A03 CWE-79

SQL Lab rendered query results as live HTML by default. A crafted payload like <img src=x onerror=alert(document.cookie)> in query results could be rendered as DOM, creating a defense-in-depth gap.

Devin's Response

Automated 11 min
  1. Label security-vulnerability applied to Issue #7
  2. GitHub Actions triggered the workflow
  3. Devin session auto-created
  4. Classified as OWASP A03, downgraded severity to Medium
  5. Traced renderResultCell → safeHtmlSpan → FilterXSS
  6. Flipped allowHTML default to false
  7. Added regression tests for XSS payloads

Appendix C

Knowledge & Playbooks

Reusable intelligence that compounds across every Devin session

Knowledge Notes

Contextual notes attached to repos or orgs. Auto-injected into sessions when relevant triggers match.

Example: Security Review Standards
  • Uses OWASP Top 10 classification (A01–A10)
  • Superset-specific patterns: parameterized queries, CSP headers, RLS filters
  • PR requirements: conventional commits, security label, advisory section
  • Test requirements: regression tests, edge cases, SupersetTestCase base

Knowledge notes ensure every Devin session follows your team's standards automatically — no need to repeat instructions.

Playbooks

Reusable, shareable prompt templates for repeated tasks. Like a custom system prompt that any team member can attach to a session.

Anatomy of a Playbook:
  • Procedure: Step-by-step actions (setup, task, delivery)
  • Specifications: Postconditions — what should be true when done
  • Advice: Correct Devin's priors, share preferred approaches
  • Forbidden Actions: Hard constraints Devin must not violate
  • Required from User: Tokens, info, or access needed
Tip: Run 2+ parallel Devins with the same playbook to quickly identify errors. Chat with Devin to help, then update the playbook for next time.
